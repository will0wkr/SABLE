# 키 분배 문제
- 대칭키 → 같은 키로 암·복호화하기에 전달의 안전이 중요!
- 키 분배는 키와 키 관련 정보를 운반하는 것.
- 키 분배 문제란 이 운반의 어려움을 말함.
- 키를 공유하는 사람이 늘어날수록 그 난도는 점차 늘어남.

# 공개 키와 대칭 키
## 대칭 키란?
- 앞서 여러 번에 걸쳐 학습했듯, 암·복호화에 같은 키를 이용하는 방식.
- 대표적인 알고리즘으로 [AES, ChaCha20](https://github.com/will0wkr/SABLE/blob/main/5%EC%A3%BC%EC%B0%A8/README.md) 등이 있으며, [블록 암호의 모드나 IV, padding](https://github.com/will0wkr/SABLE/blob/main/6%EC%A3%BC%EC%B0%A8/README.md) 같은 요소를 학습했음. 

## 공개 키란?
- 공개 키 암호, 즉 비대칭 키 암호는 키를 public/private로 나누어 사용하는 방식.
- 공개 키로부터 개인 키를 계산해낼 수 없어야 함.
### 개인 키 (private key)
- 공개 키 계산, 디지털 서명, 암호화 키 복호화 등에 쓰임.
### 공개 키 (public key)
- 알고리즘에 따라 공개 키는 개인 키로 생성된 서명 검증, 개인 키로만 풀 수 있는 암호화 등에 쓰임(공개 키🔒가 잠그고 개인 키🔓가 푸는 형태).

# 키 분배 문제 해결
- 공개 키 방식으로 키 분배 문제를 해결할 수 있음.
- **비밀 키를 직접 보내지 않아도 된다**는 특성 덕분.
```
1. 서버 측에서 공개 키 공개.
2. 클라이언트는 공개 키를 이용해 키 설정 참여.
3. 서버가 가진 개인 키 또는 서버의 DH/ECDH 개인 값으로 shared secret 계산.
4. 양쪽은 shared secret을 이용해 실제 대칭 키 생성.
5. 이후 AES나 ChaCha20 같은 방식으로 암호화.
```
- 서버가 공개 키·개인 키를 모두 가지고 있다면 위 과정 등을 거칠 수 있음.
- NIST에서는 공개 키 기술로 대칭 키 암호화 키를 설정한 후, 그 키로 다른 대칭 키를 설정하는 hybrid technique가 흔히 쓰인다고 함.

# 공개 키·대칭 키의 역할
- 쉽게 정리하면 다음과 같은 관게를 가짐.
- 대칭 키 : 실제 암호화.
- 공개 키 : 대칭 키를 안전하게 사용하기 위해 검증하는 장치.
## 공개 키 핵심
### 1. 키 생성/설정
- 공개 키 기술로 shared key 생성.
- shared key로 대칭 키 생성.
- 실제 데이터는 대칭키로 암호화.
### 2. 디지털 서명
- 서버는 개인 키로 서명, 클라이언트는 공개 키로 검증.
- 복호화가 아닌 검증을 통해 개인 키의 소유자를 판별.
### 3. 인증서/PKI
- 공개 키는 누구나 만들 수 있기에 인증서가 필요함.
- 따라서 이때 인증서(Certificate) 또는 PKI(Public Key Infrastructure) 이용.
- 인증서는 문서 하나면 PKI는 인증서를 포함한 전체 구조임. (발급 기관, 신원 확인 기관, 인증서 등 포함.)
## 공개 키 세부 유형
### 1. Key Agreement
- 공개 키로 암호화하는 것이 아니라 양쪽이 공개 값을 교환해 같은 비밀 값을 각자 계산하는 방식.
```
user 1 : usr1 개인 값 + 상대 공개 값 -> shared secret
user 2 : usr2 개인 값 + 상대 공개 값 -> 같은 shared secret
```
- DH, ECDH, ECDHE 등이 대표적이며, 비밀 키를 직접 보내지 않아도 같은 비밀 값을 만들 수 있음.
- TLS 1.3에서 주로 쓰는 방식.

### 2. KEM
- 공개 키와 개인 키의 역할을 나누는 방식
- 위에서 말한 공개 키🔒가 잠그고 개인 키🔓가 푸는 형태.

### 3. Digital Signature
- 개인 키로 서명, 공개 키로 검증.
- 인증 및 무결성, 부인 방지 등 보장.
