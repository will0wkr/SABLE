> 4주 차 정리 내용

# 1. 암호화·인코딩·해시의 차이
## 암호화란?
- [1주 차]()에서도 언급헀듯, 평문을 암호문으로 바꾸는 과정으로 자세한 내용은 앞선 과제에서 확인 가능.
- 키를 가진 사람만 다시 복호화해서 원래 데이터로 되돌릴 수 있다는 특징이 있음. 
- 즉, 기밀성을 지키기 위해 등장한 개념.

## 인코딩이란?
- 데이터를 다른 표현 형식으로 변환하는 것.
- 보안 목적보단 표현·호환성 등에 목적이 있음.
## 인코딩 등장 배경
- 특정 환경이 모든 데이터를 그대로 처리하지 못할 때 다른 형식으로 변환해야 했음.
- 대표적으로 RFC(Request for Comments : 인터넷 규격 문서 체계) 4648은 Base 인코딩이 과거 시스템처럼 US-ASCII만 다룰 수 있는 환경에서 데이터를 저장하거나 전송하기 위해 사용된다고 기술.
- 보다 다양한 환경에서 사용하기 위해 등장한 개념.
## 인코딩 예시
- Base64는 24비트 입력을 6비트씩 나누어 64개의 출력 문자로 바꾸고, 필요한 경우 = 패딩을 붙이는 식으로 원문을 변환.
- 단, 누구나 디코딩하면 원문이 나오기 때문에 Base64가 암호화라고 할 수 없음.

## 해시란?
- 해시는 임의 길이의 입력을 고정 길이의 값(Message Digest)로 변환하는 함수.
- 해시를 통해 메시지가 변조되었는지. 즉, 무결성을 검증.
## 해시 등장 배경
- 원본 전체를 저장하거나 비교하지 않고도 데이터가 변했는지 확인하기 위해 등장.
파일 다운로드 시 제공된 해시값과 내가 받은 파일의 해시값을 비교하는 식으로 파일이 중간에 변경되었는지 확인 가능.
## 해시 활용 예시
- 파일 무결성 및 비밀번호 검증, 디지털 서명 → 메시지 요약, 데이터 식별자, 등에 쓰임.
- 이중 비밀번호 저장에는 일반 SHA-256 같은 속도 지향 해시만 쓰면 안 되고, Argon2id나 bcrypt, PBKDF2처럼 느리게 설계된 해싱 알고리즘을 함께 사용해야 안전함.
- 빠른 해시 알고리즘은 공격자가 비밀번호 후보를 하나씩 확인해 보며, 실제 비밀번호와 매칭되는지 더 빠른 시간 안에 알아낼 수 있음.

## 종합
- 암호화는 기밀성, 인코딩은 형식 변환, 해시는 무결성 확인을 위해 등장한 개념이며,
- 암호화는 키를 가지고 있어야 복호화를 할 수 있기에 모두가 디코딩할 수 있는 인코딩은 암호화가 아님.

# 2. 해시의 개념 (심화)
## 해시의 세 가지 성질
1. 역성 저항성 : 해시값을 보게 되더라도 원래의 입력이 무엇인지 찾기 어려워야 함. 즉, 해시 값에서 원문이 연상되면 안 됨.
2. 제2역상 저항성 : 어떤 입력과 같은 해시값을 갖는 다른 입력을 찾기 어려워야 함. 수학적으로 봤을 때 컴퓨터엔 한계 범위가 존재하기 때문에 서로 다른 두 입력이 같은 해시값을 가질 수밖에 없음. 하나의 값이 정해진 상태에서 똑같은 해시 값을 가진 다른 입력을 찾을 수 없도록 하는 것이 목표.
3. 충돌 저항성 : 서로 다른 두 입력이 같은 해시값을 갖는 경우를 찾기 어려워야 함. 2.와 같이 역상은 무조건 존재할 수밖에 없고, 제2역상 저항성과 굉장히 유사함. 이 둘의 차이는 위 개념은 하나의 값이 정해진 상태를 가정하고, 충동 정항성은 정해진 값 없이 하나의 해시를 두 개의 입력이 똑같이 가지고 있다는 개념.

# 3. 비밀번호를 복호화하지 않는 이유.
- 비밀번호는 복호화 가능한 형태로 저장하는 것이 원칙.
- 비밀번호를 암호화해서 저장하면, 서버는 이를 복호화할 수 있는 키를 보유해야 함. 
- 하지만 이때 DB와 함께 키가 유출되면 공격자는 원문 비밀번호를 대량으로 탈취 가능.
- 따라서 비밀번호를 복호화하는 형태가 아닌 해싱 알고리즘을 이용해 검증을 진행하는 것.
- 대표적으로 패스워드에 salt나 cost factor를 붙여 password hash를 형성해 공격자가 해시 파일을 얻더라도 추측 시도의 비용을 높이는 방식을 사용함. (*salt란? 비밀번호 해싱 과정에 추가하는 사용자별 랜덤 값.)
